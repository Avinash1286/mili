# Phase 3 — teaching and visual coordination

This increment implements the teaching/visual portion of `imp.md`: the bounded tutor tool loop, editable semantic board, selection grounding, concept maps, and coordinated teaching beats. Phase 2 was approved and pushed as `80ea6eabc2ca7a47a829a16c1b3837523b960b46`. Phase 3 stays local until its own user test and push approval.

## Renderer decision

Use the project-owned SVG `BoardAdapter` and concept-map renderer. The plan expressly allows a permitted renderer behind the adapter contract. [tldraw's license](https://tldraw.dev/community/license) requires a valid production license; no license was obtained or account upgraded. The semantic scene is independent of any rendering library, so a licensed renderer can be introduced later without changing tutor tools or stored lessons. The graph renderer likewise uses stable semantic IDs and accessible lists without requiring a third-party canvas dependency.

The adapter must support pointer/keyboard selection and movement, drawing, safe text/equations, fraction and number-line models, graphs from explicit points, connectors, frames, zoom/pan/fit, undo/redo, export, and persisted changes. Rendering never evaluates model-produced code or inserts model-produced HTML. Diagram layout is deterministic from bounded semantic content. Images generated by a separate image model, 3D models, and gesture input retain their planned later implementation; neither is a dependency for semantic diagrams.

New diagram frames use deterministic placement clear of existing objects within the bounded canvas. An existing diagram keeps its location when it can still fit. A crowded board rejects a new diagram visibly instead of covering student work. Both typed and voice teaching bring the relevant new diagram into view. Voice readiness waits for the frame/viewport update to render and matches the current focus request, including successive beats that share the same board revision. Existing saved object IDs remain opaque strings, preserving Phase 2 IDs and references without remapping.

## Ownership and revisions

Board and map revisions are separate from the session revision. A transcript or playback acknowledgement must not invalidate an unrelated drawing transaction. Each board transaction carries its own ID, expected board revision and a bounded list of typed commands. The API holds its session mutation lock only around validation and persistence, and retains a bounded deduplication journal. Reusing an operation ID with a changed payload fails.

Tutor mutations cannot edit or remove student-authored board objects, or indirectly remove their attached connectors. Student map content survives tutor merges; replacement cannot erase student map work. Invalid commands, references and limits reject atomically. A stale tutor visual change produces a visible warning and an explanation without overwriting newer work.

## Teaching and playback

The model proposes tools; application code validates and executes them. Tool arguments contain semantic content and allowlisted commands, never arbitrary URLs or executable scripts. Provider rounds, repair attempts, tools, beat counts and response sizes are bounded. The direct Gemini integration stays in place; AssemblyAI supplies STT/TTS through the user's existing account.

Each teaching beat links spoken/display text, concepts, visual commands, source references, delivery state and an output epoch. Future beats do not mutate the board when the model finishes. The server applies the current beat at its boundary, sends its authoritative visual state, awaits the matching renderer acknowledgement and then starts speech. A three-second renderer timeout reports that synchronization is unavailable and explicitly falls back to narration. Subsequent beats advance on actual browser playback completion. Provider flush completion is not evidence of audible playback. The readiness gate does not establish a measured 150 ms visual/audio skew; synthesis startup follows the acknowledgement.

Interrupting invalidates pending work for the previous epoch. Already-applied visuals and student annotations remain. Reconnect restores durable state without replaying audio or reapplying tools. Captions and delivery state follow source sample progress; no independent timer guesses word timing. Provider word-boundary data is not advertised as precise live highlighting.

The current speech adapter creates a new TTS connection for each beat. Short turns are capped to keep resource use bounded, but free-plan connection limits still apply. Rate-limit failures must remain visible and recoverable; no automatic paid fallback is enabled.

## Grounding and explicit image sharing

Semantic selection contains stable shape/concept IDs and the selected board version. Missing, stale or ambiguous selections ask for clarification. The server derives trusted object content from its own session; client-supplied concept names are not authority.

The optional image explanation flow shows a crop preview and requires an explicit share action. Only that PNG crop and bounded lesson context go to the configured Gemini model, using its [documented inline image input](https://aistudio.google.com/docs/image-understanding). The server accepts PNGs at most 1024 by 1024 pixels and 1 MB decoded, checks their structure, disables tool execution for the image call, and does not persist the image in the lesson or logs. Provider retention follows the user's provider account terms. Camera streams are not part of this feature.

## Validation boundaries

Unit tests cover scene atomicity, authorship, conflicts, invalid references, deterministic geometry, map merge, selection and image limits. API/browser fixtures cover real app orchestration with injected models and speech. Those fixtures do not establish real model quality or acoustic timing. Live checks are explicit, small, opt-in provider calls; user microphone and visual testing remains the acceptance gate before Phase 4.
