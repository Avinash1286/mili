## Configure real providers

Edit the ignored `F:\mili\.env` locally. Keep credentials out of chat and source control:

```dotenv
GEMINI_API_KEY=your-local-key
GEMINI_MODEL=gemini-3.8-flash
ASSEMBLYAI_API_KEY=your-local-key
ASSEMBLYAI_VOICE_ID=aai-audrey
ASSEMBLYAI_STT_MODEL=universal-3-6-pro
```

Use a Gemini model your account can access. The current speech adapter pins the documented Universal-3.6 Pro streaming protocol. Restart the API after changing `.env`. Run `pnpm dev` from `F:\mili` and open [localhost:3000](http://localhost:3000).

Without keys, all Phase 1 samples still work and live voice controls explain that configuration is needed. A configuration flag means credentials are present, not that provider access has been verified.

## Main walkthrough

1. **Choose Live AI**, then open a lesson. Its initial tutor text should be generated by Gemini. Sample lessons continue to use prepared content and do not become live voice sessions.
2. **Test speech without a microphone.** Click **Start without microphone**. Type a short question. Confirm that the response appears once, plays through your selected system output, and its delivery label updates. The voice controls should show the tutor's current state.
3. **Stop mid-answer.** Ask for an explanation, then click **Stop tutor** while it speaks. Playback should stop promptly and never resume with the old answer. Ask a follow-up and confirm it produces a fresh response. Text already displayed remains available and is marked interrupted where appropriate.
4. **Test push to talk.** Disconnect, click **Start voice**, and grant microphone access. Hold **Hold to talk**, speak a short question, then release. Alternatively, focus the button and hold Space or Enter; the separate **Toggle** control starts/stops recording without holding a key. Expect replaceable partial text, one finalized message, one tutor response and spoken output.
5. **Test a short press.** Speak immediately after pressing, including just after starting voice. The opening words should be preserved while transcription connects. If provider startup exceeds the bounded buffer, the app should stop with a retry message rather than silently lose audio.
6. **Try selection context.** Select a concept on the board and ask “What does this do?” Check that the tutor refers to that object. Save/discard any board edits before asking another question.
7. **Try hands-free.** In **Options**, enable **Hands-free conversation**. Speak, pause, and then speak over the tutor's reply. Headphones help avoid speaker echo. Compare this with push to talk on your real microphone; automated tests cannot establish reliable echo behavior on your device.
8. **Check microphone control.** Mute the microphone and confirm its browser indicator turns off. Typed questions and tutor audio should still work. Enable it again or select another microphone from Options.
9. **Check recovery and cleanup.** Disconnect/reconnect, reload the lesson, switch browser tabs, and return. Saved conversation should remain; old queued audio must not replay. Hiding the page stops media and requires an explicit reconnect. Denying microphone permission should preserve typed input and voice output.
10. **Finish and reopen.** Finish the lesson while voice is connected. Confirm media stops, notes download still works, and the saved session reopens. Check the mobile **Study tools** view as well.

## Optional connectivity probes

The following explicitly opt into real requests using your configured accounts:

```powershell
pnpm verify:tutor --live
pnpm verify:speech --live --streaming
```

Running either command without the live flags makes no provider request. The speech probe reserves an output file in ignored `var/probes/` and refuses to overwrite an existing recording. It exercises streaming TTS, cancellation, and paced STT using the synthesized audio. Listen to its saved file; this loopback check does not verify microphone quality, laptop echo cancellation or the complete browser interaction.

## Automated checks

```powershell
pnpm typecheck
pnpm test
pnpm build
pnpm exec playwright install chromium
pnpm test:e2e
```

The voice browser tests use the real app, server orchestration and AudioWorklets with injected provider fixtures and synthetic microphone/audio. They validate interaction and transport behavior without provider credentials. The fixture entry point lives under `tests/fixtures/`; it is never loaded by the production server. Real provider tests remain a separate gate.

## What is still outside this phase

- This phase delivers short text teaching turns with streamed speech. Structured drawing tools, generated semantic diagrams, beat/board scheduling and precise recap word timing come in Phase 3.
- Accounts, PostgreSQL/Redis, source ingestion, persistent mastery, 3D, gestures and cloud deployment remain in the full plan. Current storage and socket ownership are single-process.
- Voice is English with the configured AssemblyAI voice; no unverified language or voice catalog is advertised.
- Timing diagnostics distinguish model time, TTS startup, and browser playback processing. They are not measured acoustic end-of-speech latency or proof that the plan's percentile targets have been met.
- Cancellation stops local work/playback and requests upstream cancellation when supported. It does not promise to undo already-billed provider work.

Please report the browser/device, steps, any visible error, and whether a problem affects text, microphone capture, playback or interruption. Do not include API keys. The user accepted Phase 2 after configuring the keys and completing their testing; objective latency and echo measurements remain separate work.
