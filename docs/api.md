# HTTP and voice contract

[openapi.json](openapi.json) is the generated OpenAPI3.1 description of every application Fastify operation. Run `pnpm api:spec` to regenerate it and `pnpm api:spec:check` to detect drift. Generation starts an isolated application with empty provider configuration and temporary file storage; it never reads local learner records or contacts a provider. Vercel's web build checks the generated artifact before publishing.

Request bodies come directly from shared Zod contracts, including the thirteen request schemas centralized in `packages/contracts/src/http.ts`. The generator observes registered routes, rejects undocumented operations and rejects documented routes that no longer exist. Domain schemas retain field formats, bounds and unions. Ownership, cross-field refinements, revision comparisons, consent and lease/fence checks remain server behavior; JSON Schema alone cannot express all of them.

Guest requests use the expiring Bearer credential returned by `POST /v1/guest-sessions`. Signed-in browser requests use the HttpOnly `tokai_session` cookie. Cookie mutations require the configured application `Origin`, including when a stale guest Bearer header is also present. Account ownership supersedes that stale header. A private resource is never authorized merely because a caller knows its ID.

`/auth/native-session` bridges an existing native identity into application ownership and explicitly claims the current guest. The maintained Better Auth proxy under `/api/auth` supplies password signup/signin/signout and session/Convex-token discovery. It is separate from the Fastify inventory and restricted by the exact capability allowlist described in the [deployment runbook](phase-6-deployment.md). Password recovery and email verification are not configured. The internal `/internal/jobs/execute` operation requires its service secret and current leased worker/fence; browser authentication cannot invoke it.

Errors handled by the API include a safe `code`, `message`, `requestId` and `retryable` indicator. A false indicator means a blind retry is not appropriate; refresh the resource, change the request, configure the unavailable service or wait for the stated daily reset. A true indicator does not enable automatic paid retries. Typed tutor requests, assessment attempts and card reviews carry stable request/attempt/review identifiers: reuse one only for an identical retry. Revision conflicts require a fresh read before submitting edited data.

Raw local uploads use `PUT /v1/sources/{id}/content`; production clients use the exact scoped direct-transfer URL and headers returned by upload initialization or a download-ticket operation. These capabilities are short-lived and single-use. Their private Convex `/private-transfer` destination is a separate service, not a public Vercel file URL. Retrying an exhausted transfer requires a new capability. File signatures, actual lengths, checksums, ownership and consent are checked independently of the MIME header.

The `/v1/voice` operation documents the WebSocket upgrade, while `VoiceClientEventSchema` and `VoiceServerEventSchema` describe JSON messages in its `x-websocket-events` extension. The [provider protocol](provider-protocol.md) describes binary PCM framing. Standard OpenAPI clients do not implement the bidirectional socket automatically. The client must handle playback acknowledgements, cancellation epochs, planned connection rotation and a fresh authoritative snapshot without replaying prior audio.

The generated specification contains schemas and descriptions only. It contains no real tokens, account details, provider credentials, learner content or private storage URLs.
